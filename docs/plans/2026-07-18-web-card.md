# Web Card Plugin Implementation Plan

> **For implementer:** Use TDD throughout. Write the failing test first, run it
> and confirm the expected failure, then add only enough production code to make
> it pass. Keep unrelated changes in both repositories untouched.

**Goal:** Deliver an independently packaged YuDream `web-card` plugin that
parses configured websites, renders versioned cards, replies to group links,
periodically discovers new content, and provides an administrator-only visual
and agent-assisted authoring experience.

**Architecture:** Add a plugin-scoped Secret Store to the released host SPI,
then implement the plugin as a Java 21 DDD module and Vue 3 remote package. The
runtime is split into fetch, parse, version, render, discovery, and delivery
ports so security and idempotency policies can be tested without network or
messaging side effects.

**Tech Stack:** Java 21, JUnit 5, Jackson, jsoup, Jayway JSONPath, Rome, OWASP
HTML Sanitizer, YuDream Plugin SPI, Vue 3, TypeScript, Vite,
`@yudream/plugin-sdk`, and `@yudream/components`.

**Approved design:** `docs/plans/2026-07-18-web-card-design.md`

### Step 1: Write the failing contract test

Create a test proving the public contract has no list operation and supports
only opaque-key put/get/delete operations:

```java
class PluginSecretStoreContractTest {
    @Test void exposesOnlyOpaqueSecretOperations() {
        assertThat(PluginSecretStore.class.getDeclaredMethods())
                .extracting(Method::getName)
                .containsExactlyInAnyOrder("put", "get", "delete");
    }
}
```

Run:

```powershell
mvn -pl yudream-plugins/yudream-plugin-spi -Dtest=PluginSecretStoreContractTest test
```

Expected: compilation fails because `PluginSecretStore` does not exist.

### Step 2: Add the minimal SPI

Use this public shape:

```java
public interface PluginSecretStore {
    void put(String key, byte[] secret);
    Optional<byte[]> get(String key);
    boolean delete(String key);
}
```

Add `PluginSecretStore secrets()` to `PluginContext`. Returned arrays must be
defensively copied by the host adapter.

### Step 3: Write failing host adapter tests

Cover:

- storage keys are namespaced by plugin code;
- plugin A cannot read or delete plugin B's value;
- returned byte arrays are defensive copies;
- blank keys are rejected;
- overwriting replaces the prior encrypted value;
- plaintext is absent from the persistence record.

Run:

```powershell
mvn -pl yudream-infrastructure -Dtest=PluginScopedSecretStoreTest test
```

Expected: tests fail because the adapter and context wiring are missing.

### Step 4: Implement and wire the adapter

Delegate encryption at rest to the host's existing credential/encryption
facility through an infrastructure-owned adapter. Do not expose encryption
metadata in SPI. Construct `PluginScopedSecretStore` with the current plugin
code in `PluginContextImpl` and return it from `secrets()`.
