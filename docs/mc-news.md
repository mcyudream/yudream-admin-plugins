# MC 新闻推送（mc-news）

轮询 Minecraft 官网新闻与反馈隧道版本文章，与本地缓存对比发现新内容后，调用宿主 AI 整合成中文导语，按可自定义的参量化模板推送到机器人群聊、Webhook 与订阅用户。

## 新闻源

内置三个默认源（可编辑、启停，不可删除），也可新增自定义源（上限 20）：

| 标识 | 类型 | 地址 | 默认关键词 |
| --- | --- | --- | --- |
| `mcnet-news` | `mcnet` | `https://www.minecraft.net/content/minecraftnet/language-masters/zh-hans/_jcr_content.articles.page-1.json` | `A Minecraft Java` |
| `fb-beta` | `zendesk` | `https://minecraftfeedback.zendesk.com/api/v2/help_center/en-us/sections/360001185332/articles?per_page=5` | 无 |
| `fb-release` | `zendesk` | `https://minecraftfeedback.zendesk.com/api/v2/help_center/en-us/sections/360001186971/articles?per_page=5` | 无 |

- `mcnet` 解析 minecraft.net 文章列表 JSON（`article_grid`），官网文章的稳定 ID 取自去掉语言前缀的路径（用于展示与日志；去重由标题/链接指纹负责，切换语言源不会导致重复推送）；该接口不含发布时间，以发现时间代替。
- `zendesk` 解析 Minecraft 反馈隧道帮助中心文章 API，`per_page` 直接写在 URL 中可调。
- **关键词规则**：在「新闻源」编辑弹窗里**一格一条**（每格一个关键词），留空表示不过滤；命中任一收录规则即收录，命中任一排除规则即丢弃（排除优先）。
  - 每格的三个下拉即一条规则的全部设置：动作（收录 / 排除）、范围（标题或摘要 / 标题 / 摘要 / 链接）、方式（包含这几个字 / 通配符匹配 / 正则表达式）；格子下方用一句中文复述实际效果（如「标题或摘要里出现 Snapshot 就收录」），可照此核对是否符合预期。「常用规则」可一键添加「快照 / 版本发布 / 不要基岩版 / 不要市场内容」。
  - 不懂正则也能用：缺省「包含这几个字」按**字面量**做不区分大小写的包含匹配（正则元字符 `.` `*` `^` 只当普通字符，`^Version` 匹配的是标题里真的出现 `^Version`）；需要模式匹配时再选「通配符匹配」（`*` 任意字符（不跨行）、`?` 单个字符）或「正则表达式」（标志 `i` 默认已开，可选 `m` / `s` / `u`；区分大小写用内联 `(?-i)`；不写 `^ $` 时按包含匹配）。
  - 存储仍是紧凑语法 `[!][字段:][类型:]模式`，各段均可省略、顺序任意——界面上的选择与之一一对应：排除 → `!`，范围 → `title:` / `summary:` / `url:`，方式 → `glob:` / `re:`（或 `/正则/标志`），例如 `title:re:^Version`。新闻源列表里悬停规则即显示大白话解释。
  - 保存前拦截并说明原因：正则写法有误（如「Unterminated group」）、标志非法、一格填了多行；在「包含」方式下写了 `re:` / `title:` / `!` 这类前缀时只作提醒——它们会被后端当前缀吞掉，等于把匹配方式或范围改掉了，不是要匹配的文字。
  - 单格内容上限 300 字符，每个源最多 40 格；非法正则在保存新闻源时即报错（不会留到轮询才失败），运行时若遇到历史遗留的非法规则则跳过该条、不影响同源其他规则。
  - 等价示例（紧凑语法）：`A Minecraft Java`、`/^Release\s+\d+/i`、`re:Version\s+\d+(\.\d+)+`、`glob:*Snapshot*`、`title:re:^Version`、`!re:redstone`。
- 官网 Java 版文章副标题形如 `A Minecraft Java ...`，因此 `mcnet-news` 的默认模板即为筛出 Java 版动态。

## 轮询与缓存

- 定时器每分钟检查一次，距上次轮询达到配置间隔（默认 30 分钟，5~1440）即触发；关闭开关暂停自动轮询，手动轮询不受影响。
- 新闻动态与推送设置页展示轮询状态：上次轮询时间与结果摘要、下次轮询倒计时（约数分钟，定时器粒度为 1 分钟）、进行中/已暂停标签；状态每 30 秒自动刷新。
- 每个新闻源在”新闻源”页可点”测试”即时在线抓取一次：返回源原始条数、收录条数、被排除模板丢弃条数、未命中模板条数、每条模板的命中次数与非法模板清单，以及耗时与最新标题/链接；不写缓存不推送，用于定位「为什么没匹配上」。
- 每轮拉取全部启用源，与去重记忆（`seen`：标题 / 链接 / 原始 ID 任一命中的指纹，上限 2000 条）对比：没见过的进入推送；见过的按「是否送达过」分流——已成功送达的跳过，**未送达的**（推送失败、或当时没有任何可用推送目标）进入补推队列继续尝试。
- 补推队列（`pending`）在每轮轮询里先于新内容推送：单轮最多补推 20 条，队列上限 200 条（超出淘汰最旧）；只要有至少一个推送目标送达成功即移出队列，下轮不再补推。「见过」不等于「推过」。
- 清空动态时可勾选「同时清空轮询缓存」（展示列表 + 去重记忆 + 补推队列，忽略名单保留）：勾选后源里现存的新闻在下一轮重新算「新内容」；再叠加「下次轮询重新推送现有内容」决定这批内容是重新推送一轮（勾选）还是只重建基线、一条都不推（默认不勾选）。两个选项默认均为否，接口 `POST /admin/news/clear` 的 `clearCache` / `pushOnNextPoll` 缺省即 false。命令行等价操作：`node .workbuddy/mcnews-reset-poll-cache.mjs`（加 `--dry-run` 只预览；执行前自动备份到 `.workbuddy/mcnews-cache-backup-*.json`）。
- 首次运行默认只建立基线不推送，避免启用即轰炸；可用”首次运行即推送”开关改变。首次运行的判定依据是基线时间戳（`baselineAt`，由第一次轮询写入），所以**清空缓存不会让它变回「首次运行」**——重置后会照常推送。
- 单源抓取失败记入轮询状态并跳过，不影响其他源。
- 管理端可随时”立即轮询”，其右侧有「轮询后推送」开关（默认开，整块胶囊可点、开启态加重）：关闭后本轮只回填列表并重建去重记录、一条都不推送，这些内容同时被登记进去重记忆，因此后续轮询也不会再当新内容推一遍——等价于重建一次基线。接口为 `POST /admin/poll`，请求体 `push` 缺省即 `true`。轮询状态（上次时间与结果摘要）在新闻动态与推送设置页展示。

## AI 整合与消息模板

- AI 开启时，先抓取**文章正文**再调用宿主 AI 能力：Zendesk 走帮助中心单篇文章 API 取 body；官网新闻抓文章页并截取 `article-section` 到 `<footer>` 的正文区，转成纯文本（列表项加 • 前缀、还原实体、压缩空白）。
- 默认提示词要求 AI 输出"一句话概括 + 要点列表"，保留修复的 bug（含 MC-XXXXX 编号）、新增/调整内容、版本号与对玩家/服务器管理员的实际影响，忠于原文不编造；总长约 300 字。
- 正文截取长度可配（`aiContentMaxChars`，默认 6000 字符，500~20000）；仅对进入 AI 整合的条目抓正文（受单轮条数上限控制）。正文抓取失败时回退为仅按标题/摘要整合，不阻塞推送。
- 供应商/模型留空走宿主默认；AI 关闭、超时或失败回退官方摘要。
- 系统提示词与消息模板在设置页直接预填内置默认文案，用户在其上修改即可；保存时与默认完全一致视为未自定义，仍跟随内置默认（插件升级默认文案时自动生效），也可一键恢复默认。

模板参量（点击插入，`{{name}}` 占位，未知参量渲染为空）：

| 参量 | 含义 |
| --- | --- |
| `{{title}}` | 新闻标题 |
| `{{summary}}` | 官方摘要 / 副标题（可能为空） |
| `{{aiSummary}}` | AI 导语（AI 关闭或失败时为空） |
| `{{body}}` | 推送正文：AI 导语优先，自动回退官方摘要 |
| `{{sourceName}}` / `{{sourceId}}` | 来源名称 / 标识 |
| `{{category}}` | 分类（News / Updates / Beta 等，可能为空） |
| `{{url}}` / `{{imageUrl}}` | 文章链接 / 封面图（可能为空） |
| `{{publishedAt}}` / `{{discoveredAt}}` | 发布时间 / 发现时间 |

默认模板：

```text
📰 {{title}}

{{body}}

🔗 {{url}}
来源：{{sourceName}}｜{{category}}
```

## 推送渠道

- **机器人群聊**：选择宿主消息连接与群聊；官方 QQ 机器人协议可开 Markdown 渲染，其他协议建议纯文本。
- **Webhook（全局/个人）**：向配置地址 POST JSON，载荷含 `title`、`content`（渲染后文本）、`body`、`summary`、`aiSummary`、`source`、`sourceName`、`category`、`url`、`imageUrl`、`publishedAt`、`discoveredAt`、`timestamp`、`event`；支持自定义 Header（如 Authorization）。全局目标上限 20，个人上限 5。
- **用户订阅**：持有 `plugin:mc-news:use` 权限的用户可在“我的新闻订阅”开启绑定私信推送（走宿主消息绑定）并维护个人 Webhook；个人目标仅本人可见可测。
- **同一端点的目标只投递一次**：全局目标与个人 Webhook 指向同一地址（或同一群聊连接 + 频道）时，同一篇新闻在一轮轮询里只投递一条——否则接收端会收到两条内容一模一样的推送。端点判定为「同类型 + 同地址 + 同自定义 Header」，因此 Header 不同的两个目标（如不同鉴权令牌）、不同地址、不同群聊频道都仍会各自投递，不会被误合并；轮询摘要会说明本轮跳过了几个端点重复的目标。
- 同一篇新闻投给多个目标时共用同一份 JSON 载荷（`timestamp` 一致），接收端可据此再判一次重。
- 手动推送的目标清单同样按端点合并展示（并提示「已合并 N 个同端点目标」）：勾选被合并掉的次要目标与勾选主目标等价，不会变成空推送。

## 已知行为

- 推送失败是**有记录的中间态**，不是终态：失败的条目（以及推送时没有任何可用目标的条目）进入未送达队列，后续轮询持续补推，直到至少一个目标送达成功；失败原因在推送记录中可查。
- 补推只发生一次：送达成功即刻移出队列，不会反复重试。目标长期不可用时，队列最多堆 200 条、每轮尝试 20 条，目标恢复后按轮次分批补齐。
- 补推的旧条目不会顶到动态列表最前面，而是就地刷新推送状态（`已推送`），列表顺序保持稳定。
- 推送日志按“一条新闻 × 一批目标”记录：定时轮询为 `poll`、立即轮询为 `manual`、手动推送为 `push`、测试推送为 `test`。
- **手动推送**：新闻动态列表每行可立即推送该条动态，复用与轮询完全相同的消息模板与推送目标（同样按端点去重，同一接收端只收一条）。它不改变去重判定、不改变列表顺序，也不会把该条算作新内容；推送结果写回该条状态（已推送 / 推送失败），失败或推送时没有可用目标会进入未送达队列，由后续轮询补推。若当前一个可用目标都没有，接口直接拒绝并提示（`400`），而不是静默无反应。弹窗内可以选择**推送目标**（默认全选，清单已按端点去重）：只投给勾选的目标，未勾选的目标不会收到本条消息，自动轮询不受该选择影响；若勾选的目标全部已停用，接口直接拒绝并提示（`400`）。另有「同时发送给私信订阅用户」开关（默认不勾选，仅影响开启了私信订阅的用户）。
- 新闻动态支持单条删除与一键清空，语义不同：
  - **单条删除**进入忽略名单（指纹条目，上限 500），既不推送也不会被回填，用于屏蔽不想要的条目；
  - **清空动态**默认只清空列表显示、保留去重记忆：下轮轮询把源里仍在的条目回填回列表（标记「重复未推」），已推送过的不再推送，期间真正的新内容照常推送；若某条还在未送达队列里，则仍会被补推。
  - **清空动态时可勾选「同时清空轮询缓存」**（默认不勾选）：去重记忆与未送达队列一并清空，源里现存内容会被视为新内容；忽略名单不受影响，被删除过的新闻不会被带回列表。
  - **清空缓存时还可勾选「下次轮询重新推送现有内容」**（默认不勾选，且仅在上一个选项勾选时可选）：不勾选时下一次轮询只重建基线（回填列表 + 重建去重记录）而不推送，该行为由缓存里的 `baselineOnly` 标记驱动，与「首次运行即推送」设置无关，且抓取全失败的那一轮不会消费该标记；勾选时下一次轮询把源里现有内容当作新内容重新推送一轮。弹窗会显示即将清空的去重记录与未送达队列条数。
- 忽略名单条数、去重记录条数与未送达待补推条数在新闻动态页状态卡展示；“清空忽略名单”会同时移除对应指纹，被拦截的新闻因此重新参与轮询并作为新内容再推送一次（显式恢复操作）。
- 轮询摘要为 `·` 分隔的紧凑分段文案，零值片段不出现：“抓取 30 条 · 新增 8 条 · 推送 8/8 · 跳过重复 14 条 · 忽略 2 条”“抓取 30 条 · 无新内容 · 跳过重复 22 条”“清空缓存后仅重建基线 8 条（未推送）”；有补推时追加“补推 3/3”，有源抓取失败时追加“源失败：<源名>”。
- 宿主 AI、消息连接能力缺失时对应路径显式降级：AI 回退官方摘要；无推送目标时条目标记“未推送”并进入补推队列，配置好目标后下一轮自动补推（不会因为「已见过」而被跳过）。
- 去重记忆上限 2000 条指纹（尾部最新，超出淘汰最旧），约为展示缓存上限的 10 倍，按每天个位数新增估算可覆盖数月以上；若把来源单页条数调到远超该上限，极旧条目理论上仍可能重新被发现。
- 展示缓存裁剪不影响去重：被裁掉的条目仍在去重记忆里，重新出现在源里时只会回填列表，不会重新推送（仍在未送达队列里的除外，见上）。
- 轮询推送途中执行单条删除：该条目本轮不再推送，也不会被写回列表（每次写盘都按最新忽略名单过滤）。
- 标题完全相同的两条不同新闻会被视为同一篇，只推送先出现的那条——这是“按标题去重”的已知代价。
- 历史数据（1.0.0 的展示缓存，无去重记忆）在升级后首轮会被补记成指纹，不会把已有新闻当成新内容重推一遍。
- 关键词规则只作用于「源返回的哪些条目进入候选」，与去重记忆无关：**放宽**模板（删掉排除规则、放宽正则）后，之前被挡掉的旧条目会被判定为新内容并推送一次。要避免补推，请在放宽的同时保留/补充排除模板。
- 关键词规则按源存储，改动不影响其他源；单源最多 40 条、单条上限 300 字符，匹配在轮询线程内同步执行（匹配对象是标题/摘要/链接这类短文本，正则回溯风险可控）。
